## 1. Опис проєкту

Метою роботи є опанування побудови багаторівневої навігаційної структури застосунку за допомогою **Expo Router**, налаштування захищених маршрутів на основі глобального контексту авторизації, а також оптимізація рендерингу великих масивів даних за допомогою віртуалізованих списків `FlatList` та `SectionList`.

У застосунку реалізовано дворівневу навігаційну систему з функціональними екранами:

1. **Авторизація (`login.jsx`):** публічний екран із формою входу (поля «Логін», «Пароль», кнопка «Увійти») та збереженням стану в глобальному `AuthContext`.
2. **Бічне меню (`(drawer)/_layout.jsx`):** кастомна Drawer-навігація з автентифікаційним бар'єром (редирект на `/login` для гостей), перемиканням розділів та кнопкою «Вийти».
3. **Стрічка новин (`(news)/index.jsx`):** оптимізований список на базі `FlatList` (100+ елементів) з підтримкою жесту оновлення `Pull-to-Refresh`, довантаженням `Infinite Scroll` (`onEndReached`), мемоізацією через `React.memo` та фіксованим прорахунком `getItemLayout`.
4. **Деталі новини (`(news)/[id].jsx`):** динамічний стек-екран із передачею параметрів через хук `useLocalSearchParams()` та прихованим другим заголовком (`headerShown: false`).
5. **Довідковий центр (`faq.jsx`):** структурований довідник на базі `SectionList` із тематичним групуванням чаseries запитань за розділами.

## Висновок з відповідями на контрольні питання:
1. **Як працює вкладена навігація в Expo Router?**  
   Expo Router будує навігацію за структурою папок. Кожна папка з файлом `_layout.jsx` створює свій окремий навігатор. Це дозволяє вкладати один навігатор в інший — наприклад, звичайний стек переходів між екранами `(news)` покласти всередину бічного меню `(drawer)`. А щоб не було подвійної шапки вгорі екрана, у внутрішньому макеті вимикається заголовок (`headerShown: false`).

2. **Як захистити екрани від неавторизованих користувачів?**  
   Через спільний макет `_layout.jsx` та глобальний контекст (`AuthContext`). У макеті перевіряється змінна `isAuthenticated`: якщо користувач ще не увійшов, додаток автоматично перекидає його на екран логіну за допомогою `<Redirect href="/login" />`, не відкриваючи захищені сторінки.

3. **Чим FlatList кращий за ScrollView і що таке віртуалізація?**  
   `ScrollView` одразу завантажує абсолютно весь список у пам'ять, тому на сотнях новин телефон почне сильно лагати. `FlatList` працює через **віртуалізацію**: він тримає в пам'яті та малює лише ті елементи, які видно на екрані просто зараз. А властивість `getItemLayout` допомагає списку заздалегідь знати висоту карток, щоб не витрачати ресурси на їх вимірювання при скролі.

4. **Як отримати параметри динамічного маршруту (`[id]`)?**  
   За допомогою спеціального хука `useLocalSearchParams()` з `expo-router`. Наприклад, для файлу `[id].jsx` ми просто пишемо `const { id } = useLocalSearchParams();` і отримуємо потрібний номер чи ID відкритої новини.

5. **Яку структуру даних приймає SectionList?**  
   Він приймає масив об'єктів-секцій. Головна вимога — кожен такий об'єкт обов'язково повинен мати поле `data` з масивом елементів для цієї групи (а також заголовок, наприклад `title`):
   ```javascript
   [
     { title: 'Розділ 1', data: ['Питання 1', 'Питання 2'] },
     { title: 'Розділ 2', data: ['Питання 3'] }
   ]
